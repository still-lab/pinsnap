# 全流程交付就绪度评估

评估日：对照仓库当前状态（规划文档 + 接口骨架，尚无 Xcode App）。

结论先说：**需求与技术规划已够支撑全流程；UI 设计、可运行 App、完整测试与商店呈现尚未开始。按 M0–M4 推进可以闭环上架，但缺外部前置（Apple 账号、设计资产、真机多屏验收）。**

---

## 总览矩阵

| 阶段 | 就绪度 | 仓库内已有 | 缺口 | 能否闭环 |
|---|---|---|---|---|
| 1. 需求理解 | **高 ~90%** | PRD / FEATURE_MAP / PIN_LIFECYCLE / 商业锁定 | 无交互原型稿；无正式 User Story 拆卡 | ✅ 可直接开发 |
| 2. UI 设计 | **低 ~15%** | 交互语义文字描述；模块里有 Overlay/Settings 占位 | 无视觉规范、无线框/高保真、无图标与升级页设计 | ⚠️ 可「工程默认 UI」先做，上架前需补设计 |
| 3. 功能开发 | **低 ~20%** | 模块边界、协议、状态机、Package 可编译 | 无 `.xcodeproj`、无 SCK 实现、无真实 Overlay/Pin 窗口 | ⚠️ 从 M0 起可完成，估 8–12 周 |
| 4. 单元测试 | **低 ~25%** | 测试骨架 5 例（Gate/Undo/几何占位） | 无几何真数据、无 Clipboard/Pin 生命周期测、无 UI 测 | ⚠️ 框架在，需随 M1–M3 补齐 |
| 5. 产品呈现 | **低 ~10%** | STORE_CHECKLIST 提纲 | 无截图、无 AS 文案终稿、无隐私页、无内购已建档 | ⚠️ M4 集中做；依赖 Developer 账号 |

## 分阶段说明

### 1. 需求理解 — 已具备闭环条件

**已完成**

- 对标 Snipaste / iShot 后的范围裁剪（v1.0 不做十合一）
- 成功截图定义、贴图关闭/销毁/隐藏语义
- Free≤3 / Pro 价格 / 热键 / Bundle / 系统版本全部锁定
- 需求 ID → 模块 → 里程碑映射

**仍建议补（非阻塞）**

- 把 FEATURE_MAP 拆成 issue / 看板卡（可选）
- 主路径录一段「纸面走查」视频脚本（便于 UI 对齐）

**判定：** 需求侧**可以**支撑全流程，不必再大范围调研。

### 2. UI 设计 — 当前最弱环

**已有：** 行为级说明（遮罩、工具条、贴图手势），无视觉。

**要补齐才能「产品级」呈现**

| 交付物 | 用途 | 建议时机 |
|---|---|---|
| 菜单栏图标（模板/彩色） | App / 状态栏 | M0 前或并行 |
| 截图 Overlay 线框 | 选区、工具条、放大镜布局 | M1 前 |
| 贴图右键菜单 / HUD | 穿透状态、关闭销毁 | M2–M3 |
| 设置页信息架构 | 通用/热键/存储/Pro | M0 |
| 权限深链 + 升级 Pro 页 | 审核观感 / 转化 | M0 / M2 |
| App Store 截图构图 5 张 | 上架 | M4 |
| 简中/英关键文案表 | UI + 商店 | M0 起维护 |

**务实策略（推荐）**

1. **工程默认 UI**（系统字体、SF Symbol、中性灰遮罩）先跑通 M0–M2。  
2. **并行**出一套轻量视觉（不必等完整 Design System）。  
3. M4 前替换图标、升级页、商店截图。

**判定：** 不挡「做出能用的 App」；挡「好看且可上架转化」。设计必须排进并行轨道。

### 3. 功能开发 — 规划完整，实现未开始

**已完成**

- 九模块目录与依赖规则  
- 状态机、PinStore 上限、FeatureGate、商品 ID  
- SPM 可 build（便于先测领域逻辑）

**未完成（按里程碑）**

| 里程碑 | 关键缺口 |
|---|---|
| M0 | Xcode macOS App、沙盒、菜单栏、真热键、权限深链 |
| M1 | ScreenCaptureKit 截帧、Overlay 交互、多屏几何 |
| M2 | 标注绘制、Pin NSPanel、剪贴板图、升级拦截 UI |
| M3 | 文色贴图/StoreKit 沙盒（无分组、无历史、无会话恢复、穿透暂缓） |
| M4 | 本地化、性能、提审 |

**外部依赖（人/账号）**

- Apple Developer Program  
- 至少一台 Mac + 建议外接屏测 Retina 混合缩放  
- 内购沙盒账号  

**判定：** **能**完成全功能开发；前提是执行 M0–M4，不是文档再写一轮。

### 4. 单元测试 — 可扩展，未覆盖主路径

**已有：** `FeatureGate`、`Annotation` undo、几何/上限占位测。

**必须补到「可称有单测」**

- `ScreenGeometry` 多 scale 矩阵（人造 ScreenDescriptor）  
- `ClipboardBridge` 类型矩阵  
- `PinStore` 关闭/销毁/隐藏/恢复栈  
- `FeatureGate` 第 4 张贴图拦截与 Pro 解锁  
- （可选）导出 PNG 往返  

**不做/少做**

- Overlay 像素级 UI 测试成本高 → 用 `PIN_LIFECYCLE` 手工清单  
- StoreKit → 沙盒手工 + 少量协议 mock  

**判定：** 测试**策略正确**；覆盖率要随开发长，否则 M4 不敢提审。

### 5. 产品呈现 — 清单有了，资产没有

包含：App 内体验完整度 + App Store 页 + 权限/隐私说明。

| 项 | 状态 |
|---|---|
| 应用内主路径可演示 | ❌ 尚无 App |
| 升级/设置/引导观感 | ❌ |
| AS 标题副标题关键词 | ⬜ 可写草稿 |
| AS 截图与预览视频 | ❌ |
| 隐私政策页托管 | ❌ |
| 内购展示与恢复购买 | ❌ |
| 本地化中英 | ⬜ 约定有，字符串未建 |

**判定：** 呈现是 **M4 收口项**；现在不阻塞写代码，但要预留 1–2 周，且依赖设计截图。

## 建议执行顺序（闭环最小集）

1. **本周：** M0 Xcode App + 屏幕权限深链（无引导窗）  
2. **并行：** 菜单栏图标 + Overlay/设置线框（可 Figma 一页）

5. **M4：** 换皮设计、AS 截图、隐私页、提审
